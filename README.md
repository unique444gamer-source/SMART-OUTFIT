# SMART OUTFIT — Full-Stack Fashion Store

A responsive fashion e-commerce starter built with React + Vite, Express, MongoDB and JWT authentication. The storefront and admin panel are served by one Render web service.

## Features

- Responsive storefront, category filtering, product search and product details
- Cart and wishlist persisted in the browser
- Customer registration, login, profile and order history
- Checkout with Cash on Delivery / bKash selection, coupon validation and shipping calculation
- Public order tracking by order ID
- Admin dashboard, product CRUD/archive, order status management, customer list, coupons and sales analytics
- Light/dark theme
- MongoDB seed data and initial admin account

## Requirements

- Node.js 20+
- MongoDB Atlas database (recommended for deployed persistence)

## Run locally

```bash
npm install
cp .env.example .env
# Set MONGODB_URI and a long random JWT_SECRET in .env
npm run dev
```

Frontend: http://localhost:5173  
API health: http://localhost:5000/api/health

If `MONGODB_URI` is not configured, the API still starts in demo mode but database-backed registration, orders and admin features will not persist/work. Configure MongoDB before real use.

## First admin login

Set `ADMIN_EMAIL` and `ADMIN_PASSWORD` in your environment before the first successful MongoDB connection. The server creates this admin user if it does not already exist. Change the default credentials immediately.

## Deploy to GitHub + Render

1. Create a MongoDB Atlas cluster and database user. In Atlas Network Access, allow Render outbound access (for a simple first deployment, `0.0.0.0/0`; use stricter network controls where possible).
2. Push this folder to a GitHub repository.
3. In Render, choose **New → Blueprint** and connect the repository. Render reads `render.yaml`.
4. Add `MONGODB_URI` and `ADMIN_PASSWORD` in Render environment settings. `JWT_SECRET` is generated by the Blueprint. Set a strong unique admin password.
5. Deploy. Render builds Vite into `dist`; Express serves both the API and frontend from the same service.
6. Visit `https://YOUR-SERVICE.onrender.com/api/health` and confirm `database: connected`.

Alternatively create a Render Web Service manually:
- Build command: `npm install && npm run build`
- Start command: `npm start`
- Environment: `NODE_ENV=production`, `MONGODB_URI`, `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`

## Important production notes

- The checkout currently supports Cash on Delivery and a **manual bKash arrangement** only. It does not claim to process online payments. Integrate an approved payment gateway (e.g. SSLCommerz/bKash merchant API) before accepting online payments.
- Product image URLs are stored as URLs. Add Cloudinary or another managed image-storage service before enabling direct image uploads.
- Configure HTTPS, a production-grade `JWT_SECRET`, strong admin credentials, database backups, and a proper privacy/return policy before launch.
- The starter does not yet include email/SMS notifications, shipping-carrier integrations, tax invoices or automated refunds.
- Free Render instances may sleep when idle. MongoDB Atlas is separate and stores persistent application data.
- For a live shop, test the complete order and stock workflow with test products before announcing the store.
